Nametable contains 960 tiles.
  -- Each byte in nametable contains tile id.
    -- Tile Id is address in pattern table. 
    -- Pattern table has actual "pictures".
  -- Since it uses one byte it can only reference 256 tiles per bank (2 banks)
  -- 64 bytes of nametable used for specifying color information 
  -- 960 + 64 = 1024 bytes
  -- Entirely populated by CPU using Addr/Data registers
  -- The nametable is essentially the state of the screen minus the sprites

  -- Attribute Table
    -- Made up of 16x16 meta-tiles (sometimes 32x32)
    -- 


  -- Algorithm for drawing 
    -- Determine nametable to use from Control register
    -- Determine CHR-ROM bank to use from Control register
    -- Read 960 bytes from nametable and draw 32x30 tile screen



OAM
  -- Primary OAM filled with 64 sprites worth of data (4b/sprite)
  -- Secondary OAM (8 sprites) filled with sprites to render (Evaluation phase)
    -- Cleared at start of each visible scanline
  -- Secondary OAM fills sprite output unit (Fetch phase)
    -- Sprite output units used for pixel selection against background pixel
